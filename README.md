1.0.12では、固定脚の負側仕事応答を詳しく調べるため、0・10・15・20・25 msを1回の30秒測定で繰り返す一括測定ボタンを追加しました。条件と未実行をZEROクロスごとに記録し、入力中・停止後の仕事は取得したRWLOGからPC側で計算します。まず3回、開始状態をそろえて繰り返してください。[一括測定の手順](docs/negative_work_batch_20261021.md)。

1.0.11では、負側へ向かうZEROクロスで固定幅のRAW +300 mAを与え、入力中と入力停止後の機体への仕事を測る専用試験モードを追加しました。本体Web画面の「基準0 ms」「試験15 ms」「試験30 ms」は、目標8°・300 mA・学習補正なし・正側の旧式換算制御をまとめた測定パッケージです。通常の制御モードと区別して記録します。[測定手順](docs/negative_work_probe_20261016.md)を参照してください。

1.0.10では、ホイール位置0x90の生値と読み取り前後・中点の時刻、通し番号、成否を5 ms間隔を目標に記録します。RWLOG v56（172 bytes/行）から、位置の5点近似で得た相対角速度と、同時刻の機体角速度を使って反作用の仕事を計算します。従来の速度読み値は記録と既存制御に残し、仕事の計算には使いません。位置の欠測を速度読み値で補う処理や、仕事を制御へ帰還させる処理はありません。制御の式・係数・目標角・電流と入力幅の決め方・直立基準は1.0.9から変更していません。[位置記録と仕事の計算](docs/wheel_position_work_20261016.md)を参照してください。

1.0.9では、入力中もホイール回転速度を10 ms間隔を目標に記録します。機体の角速度・取得時刻・指令適用時刻と一緒にRWLOG v55へ保存し、取得後にブラウザで反作用が機体にした仕事を計算します。入力別・全区間のCSVを保存できます。暫定慣性は `2.8×10⁻⁵ kg·m²`、回転軸の符号も解析時に変更できます。[計算と操作](docs/wheel_work_20261016.md)を参照してください。保存済みログは[ファイル解析ページ](https://temesotejam.github.io/atoms3r-lateral-energy-control/wheel-work.html)でも解析できます。新しい速度取得による実機タイミングへの影響は、次の運転ログで確認します。

実機動作・左右揺動の試験はこのリポジトリを使います。慣性やモータ応答などの部分的な機能の測定には、[測定用リポジトリ](https://github.com/temesotejam/atoms3r-motor-inertia-test)を使います。測定用のプログラムは今回変更していません。

1.0.8では、旧版0.47.31の左右別の到達角予測を位置エネルギーへ換算する制御式を追加しました。Webで「旧到達角予測をエネルギーに換算」を選ぶと、この式から必要な正方向入力を逆算し、過剰時は入力を止めます。逆入力の応答は旧式では同定されていないため、このモードではブレーキを使いません。従来の二次エネルギー式は比較用に選べます。式の根拠と実機での確認項目は[旧到達角予測とエネルギー制御の接続](docs/energy_angle_bridge_20261015.md)にまとめました。現行の直立基準を使った実機での振幅は未確認です。

1.0.7では、停止中に本体のWeb画面で「今の姿勢を直立基準として保存」を押し、約2秒間静止させて基準を取得します。本体に保存し、測定開始時に原点を取り直しません。ログ消去や通常の再起動後も同じ基準を使います。初回は基準の保存が必要です。[操作と記録の説明](docs/upright_reference_20261014.md)を参照してください。

AtomS3R、Unit Roller485、リアクションホイールを用いた左右揺動の試験用ファームウェアです。姿勢は既存のMEKFで推定します。始動後に左右の物理ピークとZEROクロスを確認し、次のピーク角を目標に近づけるため、リアクションホイールの電流入力時間を毎回計算します。測定区間は15秒です。

このリポジトリは [100 ms固定入力の試験版](https://github.com/temesotejam/atoms3r-zero-cross-fixed-100ms-test) を基にしています。モータの前後逆向き取り付けに合わせた `MOTOR_DRIVER_POLARITY=-1`、MEKF、RWLOG v54、足カメラの任意記録を引き継いでいます。

2026年10月14日の符号確認ログでは、通常入力の符号反転後に正側ピークが約8.3°、負側が約10.4°となりました（目標8°）。従来版では両側とも約1～2°でした。二次エネルギー式の比較モードでは不足時に進行方向へ入力し、余剰時には逆方向へ入力します。これらの測定ログを使って二次式の左右別の予測係数を暫定更新しました。始動キックの方向は変えていません。

## 二次エネルギー式の比較モード

1. MEKFの左右角から物理ピークとZEROクロスを検出し、ZEROクロス時の左右角速度 ω を得ます。
2. 左右別の暫定係数で、入力しなかった場合に次のピークへ残るエネルギーを `E_free = max(0, cω² − L)` と予測します。`L` は観測データから求めた実効損失であり、着地損失だけを測った値ではありません。
3. 指定した目標角 `8° / 10° / 12°` を機構の重力位置エネルギー `E_target` に変換します。同じ試行中に十分な観測が得られた場合は、左右・入力方向・入力前ホイール回転数帯ごとの予測誤差を小さく補正し、`ΔE = E_target − E_free + 積分補正 − 予測誤差補正` を計算します。正ならZEROクロス時の進行方向へ入力し、負なら逆方向へ入力します。
4. リアクションホイールの入力に必要な符号付き電流積分 `Q` を、暫定応答式 `ΔE = α|ω|Q + βQ²` から逆算します。起動前に作った電流立ち上がり表を使い、指定電流でその `Q` に近い整数ミリ秒のパルス幅を選びます。加速は最大100 ms、正側の逆入力は最大50 msです。負側の逆入力は比較試験のため0・20・50 msから上限を選べます。
5. 次のピークの位置エネルギー誤差を左右別に補正します。積分更新は、実行した入力に対応するピークだけに適用します。飽和時は同じ方向への積分を止めます。

入力電流は100〜1200 mAを10 mA刻みで選択できます。初期値は300 mAです。始動キックのみ100 ms固定です。通常入力はZEROクロス後に必要エネルギーへ応じて可変になります。設定と実際の入力、符号付きのエネルギー差と電流積分、予測値、MEKF状態、実測電流をRWLOGに記録します。

二次式で負側ブレーキを比較する場合は、目標8°、指令電流300 mAを固定し、負側のブレーキ上限だけを変えてください。二次式を選んだときの50 msは従来条件です。選択値はRWLOGの `energy_control_autonomous_negative_side_brake_width_max_ms` に記録されます。0 msでは負側の逆入力を指令しませんが、正側の入力と始動キックは従来どおりです。[比較手順](docs/negative_brake_comparison_20261014.md)を参照してください。

予測誤差補正は測定開始5秒後から学習し、同じ側・入力方向・回転数帯で同符号の誤差が4回続くまで入力には使いません。古い回転数データでは従来の計算に戻ります。3条件のログから固定の回転数係数は決められなかったため、補正は試行ごとに初期化し、絶対値を0.000070 Jに制限しています。[方式と検証範囲](docs/peak_error_adaptation_20261014.md)を参照してください。

## 係数と実機確認

1.0.6では制限前の必要エネルギーと入力、許容上限で実行できる仕事、残る予測エネルギーを分けて記録します。ピーク確認時のホイール回転数・実電流も追加しました。Web画面で予測誤差の学習補正を切り替えられます。[エネルギー式の検証手順](docs/energy_model_validation_20261014.md)に、20・50・0 msの測定順、必要量と上限の比較、実電流・無入力損失・ブレーキ応答を確認する順序をまとめました。検証では学習補正を「使用しない」にして、目標8°・300 mAをそろえてください。

最初の係数は引き継いだ固定脚データの204イベントから作りました。現在の係数は、符号を修正した後の実機ログ2件・58イベントを使って一部を更新しています。[今回の係数と誤差](docs/lateral_energy_refit_20261014.md) に、対象の記録、左右別の決め方、保存済みログへの当てはまりをまとめました。[初期係数](docs/lateral_energy_seed.json) と[初期フィットスクリプト](tools/fit_lateral_energy_seed.py) も残しています。

負側には逆入力14回の記録がありますが、その効果を無入力時の動きから独立して同定できていません。正側には無入力の記録がありません。そのため、係数は現時点の実機記録に合う暫定値であり、逆入力は50 msに制限して `energy_model_extrapolated` に記録します。次の測定では300 mAで左右別の入力方向、ZEROクロス判定、パルス幅、次ピーク、実電流をRWLOGで確認してください。16°の左右角制限と既存の異常停止は維持しています。

## ビルドと検証

```sh
python3 tools/embed_runtime_web.py --check
bash tools/test_runtime.sh
pio pkg install -e atoms3cam
pio run -e atoms3cam
```

ビルド済みバイナリはGitHub Actionsの `build` 実行結果から取得できます。Web書き込みページを使う場合は、リポジトリの Settings → Pages で GitHub Actions を公開元として有効にし、`pages` ワークフローを実行してください。Pagesを有効にするまではサイト公開を保留します。実機での閉ループ性能は、このリポジトリの自動試験だけでは確認できません。
