# AtomS3R 左右揺動エネルギー制御

AtomS3R、Unit Roller485、リアクションホイールを用いた左右揺動の試験用ファームウェアです。姿勢は既存のMEKFで推定します。始動後に左右の物理ピークとZEROクロスを確認し、次のピーク角を目標に近づけるため、リアクションホイールの電流入力時間を毎回計算します。測定区間は15秒です。

このリポジトリは [100 ms固定入力の試験版](https://github.com/temesotejam/atoms3r-zero-cross-fixed-100ms-test) を基にしています。モータの前後逆向き取り付けに合わせた `MOTOR_DRIVER_POLARITY=-1`、MEKF、RWLOG v54、足カメラの任意記録を引き継いでいます。

2026年10月14日の符号確認ログでは、通常入力の符号反転後に正側ピークが約8.3°、負側が約10.4°となりました（目標8°）。従来版では両側とも約1～2°でした。現在は不足時に進行方向へ入力し、余剰時には逆方向へ入力する符号付きエネルギー制御を試します。始動キックの方向は変えていません。

## 制御の流れ

1. MEKFの左右角から物理ピークとZEROクロスを検出し、ZEROクロス時の左右角速度 ω を得ます。
2. 左右別の暫定係数で、入力しなかった場合に次のピークへ残るエネルギーを `E_free = max(0, cω² − L)` と予測します。`L` は観測データから求めた実効損失であり、着地損失だけを測った値ではありません。
3. 指定した目標角 `8° / 10° / 12°` を機構の重力位置エネルギー `E_target` に変換し、符号付きの `ΔE = E_target − E_free + 左右別の補正量` を計算します。正ならZEROクロス時の進行方向へ入力し、負なら逆方向へ入力します。
4. リアクションホイールの入力に必要な符号付き電流積分 `Q` を、暫定応答式 `ΔE = α|ω|Q + βQ²` から逆算します。起動前に作った電流立ち上がり表を使い、指定電流でその `Q` に近い整数ミリ秒のパルス幅を選びます。加速は最大100 ms、逆入力は最大50 msです。
5. 次のピークの位置エネルギー誤差を左右別に補正します。積分更新は、実行した入力に対応するピークだけに適用します。飽和時は同じ方向への積分を止めます。

入力電流は100〜1200 mAを10 mA刻みで選択できます。初期値は300 mAです。始動キックのみ100 ms固定です。通常入力はZEROクロス後に必要エネルギーへ応じて可変になります。設定と実際の入力、符号付きのエネルギー差と電流積分、予測値、MEKF状態、実測電流をRWLOGに記録します。

## 係数と実機確認

暫定係数は引き継いだ固定脚データの204イベントから作りました。元データの `Q` は実電流の独立した積分ではなく予測値です。このデータだけでホイールが加えたエネルギーを因果的に同定したとは言えません。係数の式・範囲・誤差は [係数データ](docs/lateral_energy_seed.json)、再計算方法は [フィットスクリプト](tools/fit_lateral_energy_seed.py) にあります。

逆入力の係数は実測から同定されていません。上式の負の `Q` は正方向入力だけから得た係数の外挿です。逆入力は50 msに制限し、実行した判定を `energy_model_extrapolated` で記録します。まず300 mAで、両側の入力方向、ZEROクロス判定、パルス幅、次ピーク、実電流をRWLOGで確認してください。実機の自由減衰と正逆それぞれ複数の入力幅の試験から、左右別の実効損失と入力応答を再同定してください。16°の左右角制限と既存の異常停止は維持しています。

## ビルドと検証

```sh
python3 tools/embed_runtime_web.py --check
bash tools/test_runtime.sh
pio pkg install -e atoms3cam
pio run -e atoms3cam
```

ビルド済みバイナリはGitHub Actionsの `build` 実行結果から取得できます。Web書き込みページを使う場合は、リポジトリの Settings → Pages で GitHub Actions を公開元として有効にし、`pages` ワークフローを実行してください。Pagesを有効にするまではサイト公開を保留します。実機での閉ループ性能は、このリポジトリの自動試験だけでは確認できません。
