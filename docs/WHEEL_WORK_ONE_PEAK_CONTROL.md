# ホイールの仕事を使う次ピーク制御（1.0.23）

## 実機での手順

脚の前後移動を従来と同じように固定する。直立姿勢で「今の姿勢を直立基準として保存」を押し、本体に `1.0.23-wheel-work-control` を書き込んだ後、「仕事に基づく制御で15秒測定を開始」を押す。終了後はRWLOGを保存する。初回は目標8°のまま試す。正負それぞれのピーク、入力電流と時間、ホイール速度、電池電圧、`q_saturated_lower/upper`、`energy_model_extrapolated`、姿勢推定の有効性を確認する。

## 制御の計算

ZEROクロス時の機体角速度を `ω₀`、ホイール回転数を `n`、電池電圧を `V` とする。正側は候補電流300・350・400 mA、候補時間40～100 msを走査する。電流応答モデルから各候補の電流時間積分 `Q` を計算し、入力中と停止後から次ピークまでのホイール仕事を合わせた値を次で予測する。仕事・エネルギーの単位はmJ、`ω₀`はrad/s、`Q`はmA·sである。

```text
Ŵ₊ = 0.587696 + 1.409246·Q·rate_dps/1000
      − 0.687560·n/500 − 0.045594·(V_mV−7350)/100
Ê₊ = −0.107202 + 0.449784·ω₀² + 0.364005·Ŵ₊
```

負側は300 mAで30・35・40 msを候補とする。

```text
Ŵ₋ = −0.359942 − 0.167041·(time_ms−35)/10
      + 0.009134·(rate_dps−65)/20 + 0.161829·n/500
      + 0.002597·(V_mV−7400)/100
Ê₋ = 0.248653 + 0.532558·ω₀² + 0.225709·Ŵ₋
```

目標8°の位置エネルギーは約0.733 mJである。各候補の `|Ê−0.733|` が最小になる入力を選ぶ。目標が候補から届く範囲外なら、その事実を飽和フラグに記録し、測定範囲外の長いパルスへ外挿しない。正側の`Q`は測定済み8.79588～15.33208 mA·sの候補だけを許可する。

角速度・入力前ホイール速度・電圧が測定時の範囲から外れるか、ホイール速度が古い場合、正側は従来の角度橋渡し式を使い、負側の出力は見送る。直前の正側ピークが7°未満のときも負側の出力を見送る。仕事の係数0.364005と0.225709は測定ログから求めた予測用の値であり、機械的な効率を意味しない。

## 適用条件と検証結果

正側の仕事モデルは2026年10月23日の一括測定5件のうち4件で学習し、残した低電圧の1件で次ピーク角のRMSEが0.245°だった。従来式は同じ記録で0.295°だった。正側で許す範囲はZEROクロス角速度48.3821～58.9332°/s、入力前ホイール速度213.22～394.61 rpm、電圧7.28～7.40 Vである。

負側は30・35・40 msの測定5件と、新しい40 ms固定の測定5件を合わせ、各群の最後の1件を検証に残した。負側で許す範囲は角速度63.9133～74.0667°/s、ホイール速度214.89～575.79 rpm、電圧7.28～7.57 Vである。旧群の検証RMSEは0.273°、新群は0.169°だった。40 msまでの測定では負側ピーク平均は約9°であり、**この版で負側を8°にそろえられる保証はない**。今回の実機測定は、入力を上記の範囲に制限したまま、予測と実測の差、および正側入力が次の負側ピークへ及ぼす影響を確認する段階である。

モデル同定の計算と保留データでの検証は、作業フォルダーの `outputs/energy_work_validation_20261023/positive_current_batch_20261023/検証結果.md` に記録した。元のRWLOGは変更していない。

制御の候補走査はZEROクロス時だけ呼ぶ独立関数へ分けた。今回のビルドで高速領域に置く運動・取得関数本体は24,717 bytesであり、検査上限を従来の24 KiBから25 KiBへ改めた。これはIRAM全体の使用量や実機の処理時間を示す値ではないため、実機ログの処理期限超過カウンタも確認する。
