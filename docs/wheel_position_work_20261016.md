# ホイール位置から機体にした仕事を計算する（1.0.10）

## 変更の目的

固定試験fc56c9dfの24パルスでは、位置変化から求めた速度のピークに対し、
速度0x60のピークが約90～130 ms遅れた。仕事を計算するときは、ホイールの
加減速と機体角速度を同じ時刻で組み合わせる必要があるため、位置の記録を追加する。

制御の式・係数・目標角・電流指令の符号・入力幅の決め方は1.0.9のまま。
既存制御が使う速度0x60も従来10 ms目標のまま残す。
位置は測定後の解析だけに使い、仕事や位置由来速度を制御へ帰還しない。
部品測定用atoms3r-motor-inertia-testは変更しない。

## 取得と記録

専用Roller I/Oタスクが0x90を5 ms間隔を目標に読み、RWLOG v56へ保存する。

- 符号付き32bitの累積位置（100分の1度）、読取開始・中点・終了時刻。
- 失敗を含む試行ごとの通し番号、成否。INT32_MINも有効な位置値として保存。
- 従来どおりの速度とその時刻、機体角速度とジャイロ時刻、成功した指令適用時刻。

位置は追加の物理センサではなく、速度と同じエンコーダからの別計算経路。
位置に内部処理の遅れが一切ないと校正したわけではない。
ホスト読取時刻も、エンコーダ内部の取得時刻とは異なる。

追加の読取はタイムアウト2 msで制限する。未処理の電流変更を検出したときは
追加読取を後回しにする。進行中のI2C取引をSTOPが中断することはできない。
位置読取の失敗は成否と連番で解析へ伝え、位置の欠測を制御の新しい停止条件にはしない。
既存の電流・電圧・エラー確認、停止処理は維持する。

ログは通常20 ms、入力中2 msに加え、位置・速度・適用指令の連番が変わると保存する。
1行172 bytes。5 MiBのサンプル領域では30481行を保持でき、15秒の通常測定を想定する。
上限に達したときの既存の停止処理は維持する。

## 計算

1. 同じ位置連番の重複を除き、連続する位置を符号付き32bitの周回を考慮してつなぐ。
2. 位置5点を実際の読取中点時刻に対する二次式で近似し、中心の角速度を求める。
   5 ms取得なら約20 ms幅。公称周期で割る計算や、360度ごとの都合のよい折返し補正はしない。
3. 同じ時刻の機体角速度を、前後のジャイロ時刻から線形補間する。外挿しない。
4. ホイールの相対角速度から絶対角速度を作り、反作用の仕事を積算する。

```
omega_relative = s * position_to_speed_sign * d(position_deg)/dt * pi/180
omega_absolute = omega_relative + Omega
W = -J * sum(mean(Omega) * delta(omega_absolute))
```

Jはホイール・錘・モータ回転部分を含む暫定値2.8e-5 kg m²。
s=-1は機体の正方向（センサ+gy）とエンコーダ正方向の暫定対応で、解析画面から±1に変更できる。
position_to_speed_sign=+1は固定試験で確認した位置と速度の正方向の対応。
Omegaは従来のphysical_roll_rate_dps（+gyから起動時yバイアスを除いた値）。

仕事は回転子の絶対自転エネルギーを除いた機体への反作用偶力の仕事。
ホイール自体の運動エネルギーの減少や、次のピークに残るエネルギーとは異なる。
回転子共回り慣性を機体側に含む別のエネルギー定義と混ぜて二重計上しない。
直接ホイールへ働く空気抵抗は無視し、位置変化から分からない損失の内訳は推定しない。
高さ141 mmをトルクの腕として掛ける処理はない。

## 未算出と精度

- 位置読取失敗、3 ms超の取引、通し番号の飛び、非単調時刻、位置間隔15 ms超を近似へ混ぜない。
- 6000 rpmを超える位置差（量子化許容1度）や近似残差0.5度超を不連続・近似不良として拒否。
  この6000 rpmは解析上の不連続検査であり、実機の回転数許容条件を変更するものではない。
- 位置速度点の間隔30 ms超、機体角速度の前後間隔25 ms超の区間は仕事を計算しない。
- 欠測した位置を従来のRPMで埋めず、未算出をゼロ仕事とは扱わない。
- 最初と最後の位置2点ずつは近似の前後がそろわず、外挿しない。計算対象割合へ反映する。
- 入力境界は成功した指令書込完了時刻で分割し、前後の速度点から線形補間する。
  5点近似が境界をまたぐため、特に30 ms程度の短い入力では前後へのにじみが残る。
- 計算対象割合は記録のそろい方であり、物理モデルや絶対精度の保証ではない。

## 操作

1. 公開Webから1.0.10-lateral-position-workを書き込む。
2. 従来と同じ前後固定・左右揺動の条件で、目標角と電流などをそろえて測定する。
   ホイール単体の固定試験へ切り替える必要はない。
3. 測定後に「RWLOGを取得・再開」。CRC確認後、仕事を自動計算する。
4. 入力別CSV・全区間CSV・位置由来の速度CSVを保存する。
   保存済みファイルは公開ページwheel-work.htmlでも計算できる。

CLIも同じ計算実装を使う。

```
node tools/analyze_wheel_work.js RUN.rwlog OUTPUT_DIR
python tools/convert_rwlog_to_csv.py RUN.rwlog --out OUTPUT_DIR
```

v55の旧ログは従来のRPMを使う参考値として識別表示する。位置を復元した結果ではない。

## 検証

解析解のある位置・機体角速度、機体固定で仕事ゼロ、機体加速時の絶対角速度補正、
位置とホスト時刻の32bit周回、欠測・重複・CRC・指令境界・非等間隔時刻をホスト試験する。
C++実際のログからJS/Pythonの両方で位置生値と時刻が読めることを確認する。
制御ソースを1.0.9と比較し、制御の変更がないことを検証する。
ビルド・ホスト試験と実機での取得周期や停止遅延の確認は別。追加I2C負荷は次のログで確認する。
