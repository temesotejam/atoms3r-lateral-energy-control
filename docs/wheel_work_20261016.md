# ホイールの加減速が機体にした仕事（1.0.9・旧RPM方式）

現行1.0.10は[位置変化を使う方式](wheel_position_work_20261016.md)へ変更した。以下はRWLOG v55の旧方式の記録。固定試験で速度読み値の大きな遅れが確認されたため、入力中と入力後の配分を物理的な結論には使わない。

## 使用するプログラム

実機の左右揺動運転は、この `atoms3r-lateral-energy-control` で行う。
ホイールの慣性・モータ応答など、部分的な機能の測定は別の
`atoms3r-motor-inertia-test` で行う。今回、測定用リポジトリは変更しない。

1.0.9は運転中の観測と測定後の解析を追加する版。既存の到達角予測・
エネルギー制御・電流指令の符号・入力時間の選び方はそのまま使う。
今回の仕事を制御に帰還させる処理は追加しない。

## 記録

- SPEED_READBACK 0x60を入力中・入力外とも10 ms間隔を目標に読む。
- I2Cの専用タスクで読み、読み取り前後のホスト時刻と中点、試行番号、
  成否を記録する。追加の速度読み取りだけI2Cタイムアウトを2 msにする。
  実際の取引所要時間はログで確認する。STOPが来ても処理中のI2Cは中断できない。
- 未処理の電流指令変更があれば、速度と通常ステータスの追加読み取りを後回しにする。
- 速度試行番号・適用指令番号が変わったら、通常の20 ms周期を待たずにログを残す。
  入力中の従来の2 msログも維持する。
- 機体の角速度は既存の `physical_roll_rate_dps`、すなわちセンサ+gyから
  起動時のyバイアスを引いた値。角速度のジャイロ時刻も保存する。
  左右を主とする平面運動を想定する。大きな三次元運動のEuler角微分ではない。
- 実際に電流・出力レジスタの書き込みが完了した時刻と指令値を保存する。
  これはトルクの実際の立ち上がりを測った時刻ではない。

## 計算

慣性は回転するホイール・錘・モータ回転部分を合わせた暫定値
`J = 2.8e-5 kg m²`。200 KVから仮定したトルク定数に依存しており、絶対校正済みではない。

モータの生の回転速度をn [rpm]、機体の角速度をΩ [rad/s]として、

```
omega_relative = s * (2*pi/60) * n
omega_absolute = omega_relative + Omega
work_i = -J * (Omega_i + Omega_(i+1))/2
            * (omega_absolute_(i+1) - omega_absolute_i)
```

を足し合わせる。ホイールに直接働く空気抵抗は無視する。
`s=-1`を現在の取り付けに対する暫定値とする。電流指令の符号とエンコーダの
物理的な正方向は別なので、解析画面で±1を変更し、元のログを変えずに再計算できる。
解析CSVにも使用したJとsを保存する。正の仕事は加振、負は制動を表す。

これはホイールの絶対回転エネルギーを除いた機体に、反作用の偶力がした仕事。
`-Delta(0.5*J*omega_absolute²)`とは異なる。機体の揺動エネルギー式を今後作る際、
回転子の共回り分を機体の慣性に含める定義なら、対応する一般化入力は
`-J*d(omega_relative)/dt`になる。絶対速度を用いた反作用仕事との二重計上を避ける。

測った速度変化には軸受などの機体との相互作用も含まれるため、同じ損失トルクを
反作用からもう一度引かない。足裏・接触などによる損失は別であり、この仕事を
そのまま次ピークに残るエネルギーと解釈しない。高さ141 mmを腕の長さとして掛けない。

## 解析と操作

1. 1.0.9を実機に書き込み、従来と同じ条件で運転する。
2. 測定後、実機Webの「RWLOGを取得・再開」を押す。
3. 取得・CRC確認後、「ホイールが機体に与えた仕事」に結果が出る。
4. 入力別CSV・全区間CSVを保存する。Jと符号を変えたら再計算する。
5. 保存済みのファイルは公開ページの `wheel-work.html` でも解析できる。
   ファイルはブラウザ内で処理する。旧ログに入力中の速度を補うことはできない。

コマンドラインでも同じJavaScriptを使える。

```
node tools/analyze_wheel_work.js RUN.rwlog OUTPUT_DIR
node tools/analyze_wheel_work.js RUN.rwlog OUTPUT_DIR -1 0.000028
python tools/convert_rwlog_to_csv.py RUN.rwlog OUTPUT_DIR
```

最後のPythonコマンドは生の時系列・既存のイベントをCSVへ変換する。
仕事の計算は先のNodeコマンドまたはブラウザで行う。

## 欠測と時間の扱い

角速度をホイールのホスト読取中点へ線形補間する。前後のジャイロ記録がない、
その間隔が25 msを超える、速度間隔が30 msを超える、試行番号が飛ぶ、
速度読み取りが失敗する、取引が3 msを超える場合は、その区間を仕事に加えない。
同じ試行番号の重複行を重複積分しない。micros()の32ビット周回を扱う。
読み取り時刻は内部エンコーダの測定時刻ではない。

入力の開始・終了は、成功した指令書き込みの完了時刻で区切り、前後の速度点から
線形補間する。入力中の仕事と、入力を切った後の仕事は分けて保存する。
境界補間の有無、計算対象時間の割合、観測できた終了指令の有無を出す。
全区間CSVの `valid=false` は仕事がゼロという意味ではなく未算出。

計算対象の割合は記録のそろい方を表す。J・軸の符号・速度読み値の遅れ・
平面近似の正しさを保証する値ではない。速度と実電流の内部平滑化・遅れを、
今回のデータから無理に同定して補正することはしない。

## 検証

既知の角速度と回転速度変化による0.307 mJ、符号反転、機体固定で仕事ゼロ、
絶対回転速度補正、欠測・重複・CRC・周回・入力境界をホスト試験で確認する。
実機での新しいI2C負荷と読み値の時間特性は、運転後のログで確認する。
